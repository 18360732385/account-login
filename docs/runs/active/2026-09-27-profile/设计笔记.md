## 环 1 澄清（grill）— 共享理解

需求来源：用户任务附带的需求说明（已原样落盘为 `docs/requirements/个人资料.md`）。仓库现状取自根/分册 AGENTS、`docs/api`、`docs/func` 真相与代码。

| # | 问题 | 结论（共享理解） | 依据 |
|---|---|---|---|
| Q1 | 与既有 `GET /api/me`（返回 `username, displayName`）的关系？ | **保留** `/api/me` 不变（登录态探测仍用它）；新增独立资源 `/api/users/me` 承载资料读写 | 需求只要求新增；改旧接口会破坏既有前端与测试 |
| Q2 | `nickname` 与既有 `displayName` 是否合并？ | **不合并**。`displayName` 为系统显示名（预置中文名/注册=用户名），`nickname` 为用户自填、可空 | 需求：迁移后两字段为空；合并会让预置用户昵称非空 |
| Q3 | 「迁移」含义？ | 本仓无数据库（内存 `DemoUserStore`）；预置用户 demo/admin 与新注册用户 `nickname=null`、`email=null`；`createdAt` 预置用户=进程启动时刻，注册用户=注册时刻 | backend/AGENTS「库表迁移：none」 |
| Q4 | `PUT` 中字段缺省 / `null` / 空串语义？ | 缺省或 `null` = 不修改；去首尾空格后为空串 = 清空（置 `null`）；其余按规则校验 | 需求「`{ nickname?, email? }`」+「email 可为空」 |
| Q5 | 昵称长度按什么计？ | 去首尾空格后按 Unicode 码点计 1–20 | 需求「1–20 字符，去首尾空格」 |
| Q6 | 邮箱格式与唯一性口径？ | 去首尾空格；正则 `^[^\s@]+@[^\s@]+\.[^\s@]+$` 且 ≤100 字符；**不区分大小写**判重（排除本人） | 需求「合法邮箱格式、全局唯一」；大小写不敏感是邮箱常识 |
| Q7 | 「字段级错误」响应形状？ | 沿用 `ErrorResponse{code,message}`，**追加可选** `fieldErrors: {字段: 文案}`（仅校验失败时出现，JSON 省略 null）；`message` 取首个字段错误 | 保持错误体向后兼容 |
| Q8 | 409 形状？ | 409 `{code:"409 CONFLICT", message:"该邮箱已被使用", fieldErrors:{email:"该邮箱已被使用"}}` | 前端需在邮箱字段下显示同一文案 |
| Q9 | 用户名不可修改如何体现？ | 请求 DTO 无 `username` 字段；传入会被忽略（Jackson 默认忽略未知字段），响应中 `username` 不变 | 需求「用户名不可修改」 |
| Q10 | 前端「受保护路由 `/profile`」——仓内无路由库？ | **不引入** react-router（frontend/AGENTS：推荐栈无路由库，禁用未经确认的新库）；在 `App.tsx` 用 `window.location.pathname` + `history.pushState/replaceState` + `popstate` 实现最小路由：`/`（首页）、`/profile`（受保护）、`/login` | frontend/AGENTS「栈与禁用清单」+ karpathy「Simplicity First」 |
| Q11 | 未登录访问 `/profile`、资料接口 401 时？ | 清会话 → `replaceState('/login')` 显示登录表单；登录成功后回跳 `/profile`；401 场景额外提示「登录已失效，请重新登录」 | 需求「401 时跳转登录页」「未登录重定向」 |
| Q12 | 会话存储（O13）？ | `memory`（沿用：token 仅在 `App` state，刷新即需重新登录） | frontend/AGENTS「登录态」 |
| Q13 | 跨仓配对？ | 无；同仓 monorepo（`layout=monorepo`，packages backend/api · frontend/web） | start 5b |

未决：无。术语/ADR 草稿：本环无落盘（未写根 `CONTEXT.md`）。

## 环 2 设计（design）— 设计确认摘要

方案对比（仅列关键取舍）：

| 取舍点 | 方案 A（选） | 方案 B | 选 A 理由 |
|---|---|---|---|
| 后端落点 | 新 `UserController`（`/api/users`）+ 新 `UserProfileService` | 塞进 `AuthController`/`AuthService` | 资源不同（users vs auth）；AuthService 已承担 5 个用例，单一职责 |
| 字段校验 | Service 内手工校验（trim 后再判长度/格式），抛 `FieldValidationException` → `GlobalExceptionHandler` 400 | DTO Bean Validation `@Size/@Email` | Bean Validation 在 trim 之前执行，无法表达「去首尾空格后 1–20」；且需聚合多字段错误 |
| 邮箱唯一 | `DemoUserStore.updateProfile` 内 `synchronized` 判重+写入 | Service 先查再写 | 内存仓并发下原子判重 |
| 错误体 | `ErrorResponse` 追加 `fieldErrors`（`@JsonInclude(NON_NULL)`） | 新建 `ValidationErrorResponse` | 前端 `parseError` 单一路径；既有响应 JSON 不变 |
| 前端路由 | 手写最小路由（见 Q10） | 引入 react-router | 不引入新依赖 |
| 前端结构 | 新 `components/ProfilePage.tsx`（自取数：`fetchProfile`/`updateProfile`）+ `components/NavBar.tsx`；`App.tsx` 负责路由与会话 | 全部塞 App | 与既有组件粒度一致 |

后端设计：
- `DemoUser` record 追加 `nickname`、`email`、`createdAt(Instant)`；预置/注册用户 nickname/email 为 null。
- `DemoUserStore`：`updateProfile(username, nickname, email)`（邮箱冲突抛 `IllegalStateException`）、`resetProfile(username)`（测试辅助，P2 同类）。
- `UserProfileService.get(username)` / `update(username, UpdateProfileRequest)`；`UserProfileResponse(username, nickname, email, createdAt)`。
- `SecurityConfig` 无需改动（`anyRequest().authenticated()` 已覆盖；401 沿用入口点）。

前端设计：
- `types.ts`：`UserProfileResponse`、`UpdateProfileRequest`；`ErrorResponse.fieldErrors?`。
- `client.ts`：`fetchProfile`、`updateProfile`；`ApiError` 追加 `fieldErrors?`。
- `ProfilePage`：加载态 → 只读用户名/注册时间 + 可编辑昵称/邮箱；前端同口径校验；提交中按钮禁用（「保存中…」）；成功「资料已更新」；409 邮箱字段下「该邮箱已被使用」；400 按 `fieldErrors` 落到字段；401 调 `onUnauthorized`。
- `NavBar`：登录后显示「首页」「个人资料」入口。

范围外（YAGNI）：修改用户名、头像、邮箱验证邮件、持久化。
