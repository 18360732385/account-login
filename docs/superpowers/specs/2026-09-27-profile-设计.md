## 背景与目标

已登录用户可在「个人资料」页查看自己的账号信息，并修改昵称和邮箱。后端新增 `GET/PUT /api/users/me`，前端新增受保护路由 `/profile`。

## 术语

| 术语 | 含义 |
|---|---|
| `nickname` 昵称 | 用户自填，可空；去首尾空格后 1–20 字符（Unicode 码点） |
| `email` 邮箱 | 用户自填，可空；合法格式、≤100 字符、全局唯一（不区分大小写） |
| `displayName` 显示名 | 既有字段（`GET /api/me`），系统生成，**与 nickname 无关、本主题不改** |
| `createdAt` 注册时间 | ISO-8601 UTC 时刻（`Instant`）；预置用户为进程启动时刻 |

## 验收标准

| ID | 验收标准 |
|---|---|
| AC-1 | 持有效 JWT 调 `GET /api/users/me` 返回 200 `{username, nickname, email, createdAt}`，不含密码哈希等其他字段；新/预置用户 nickname、email 为 `null` |
| AC-2 | `PUT /api/users/me` 合法 `{nickname, email}` 返回 200 更新后的资料；nickname/email 去首尾空格后存储；再次 GET 可读到 |
| AC-3 | nickname 去空格后 >20 字符 → 400，`fieldErrors.nickname="昵称长度须为 1–20 个字符"` |
| AC-4 | email 格式非法 → 400，`fieldErrors.email="邮箱格式不正确"` |
| AC-5 | email 已被**其他**用户占用（不区分大小写）→ 409 `message="该邮箱已被使用"`；本人重复提交自己的邮箱不算冲突 |
| AC-6 | 未带 token / token 无效 / 已吊销 → `GET`、`PUT` 均 401 `{code:"UNAUTHORIZED", message:"需要登录"}` |
| AC-7 | 请求体携带 `username` 被忽略，用户名不可修改；字段缺省/`null` = 不修改；空串 = 清空 |
| AC-8 | 登录后导航栏显示「个人资料」入口，点击进入 `/profile`，展示用户名（只读）、注册时间（只读）、昵称与邮箱（可编辑） |
| AC-9 | 前端同口径校验：昵称超长、邮箱格式错时在字段下提示且不发请求 |
| AC-10 | 提交中「保存」按钮禁用；成功显示「资料已更新」 |
| AC-11 | 服务端 409 时在邮箱字段下显示「该邮箱已被使用」 |
| AC-12 | 未登录访问 `/profile` 重定向到 `/login`（显示登录表单），登录后回到 `/profile`；资料接口返回 401 时清会话并跳转登录页 |
| AC-13 | 既有接口与页面行为不回归：`mvn -q -f backend test`、`npm --prefix frontend test`/`run build`/`run lint` 全绿 |

## API

后端路径：`backend/src/main/java/com/example/accountlogin/`

| 方法 | 路径 | 鉴权 | 请求 | 成功响应 | 错误 |
|---|---|---|---|---|---|
| GET | `/api/users/me` | Bearer | — | 200 `UserProfileResponse` | 401 |
| PUT | `/api/users/me` | Bearer | `UpdateProfileRequest { nickname?: string\|null, email?: string\|null }` | 200 `UserProfileResponse` | 400（字段级）/ 409 / 401 |

- `UserProfileResponse { username: string, nickname: string|null, email: string|null, createdAt: string(ISO-8601) }`
- 错误体（**追加式**公共变更）：`ErrorResponse { code, message, fieldErrors? }`，`fieldErrors` 为 `{字段名: 中文文案}`，仅校验失败/邮箱冲突时出现；其余错误 JSON 与现状一致（`@JsonInclude(NON_NULL)`）。既有 Bean Validation 400 也同步带上 `fieldErrors`（追加，不改 `code/message`）。
- 校验顺序：nickname → email（全部收集后一次返回）；`message` = 首个字段错误文案。
- 代码落点：
  - `controller/UserController.java`（新，`@RequestMapping("/api/users")`）
  - `service/UserProfileService.java`（新）· `service/FieldValidationException.java`（新）
  - `service/DemoUser.java`（+`nickname`,`email`,`createdAt`）· `service/DemoUserStore.java`（+`updateProfile`,`resetProfile`）
  - `dto/UserProfileResponse.java` · `dto/UpdateProfileRequest.java`（新）· `dto/ErrorResponse.java`（+`fieldErrors`）
  - `controller/GlobalExceptionHandler.java`（+`FieldValidationException` 处理；校验失败带 `fieldErrors`）
  - `SecurityConfig` 不改（`anyRequest().authenticated()` 已覆盖，401 入口点沿用）
- 契约同步：新建 `docs/api/modules/02-account-login-user.md`；`docs/api/api.md` 索引登记；`01-account-login-auth.md` 公共约定补 `fieldErrors`；`docs/func/modules/01-account-login-backend.md` 补 `UserProfileService` 与 `DemoUserStore` 新方法。

## UI

前端路径：`frontend/src/`

- 路由：不引入路由库；`App.tsx` 内最小路由（`window.location.pathname` + `history.pushState/replaceState` + `popstate`）：`/` 首页（既有 `ProfileView`）、`/profile` 受保护、`/login` 登录。
- `components/NavBar.tsx`（新）：登录后显示「首页」「个人资料」。
- `components/ProfilePage.tsx`（新）：挂载时 `fetchProfile`；展示用户名、注册时间（只读，`toLocaleString('zh-CN')`）；昵称、邮箱输入框；校验同后端口径；提交按钮「保存」→ 提交中「保存中…」且禁用；成功「资料已更新」；409 → 邮箱字段下「该邮箱已被使用」；400 → 按 `fieldErrors` 显示；401 → `onUnauthorized()`。
- `api/types.ts`：`UserProfileResponse`、`UpdateProfileRequest`、`ErrorResponse.fieldErrors?`；`api/client.ts`：`fetchProfile`、`updateProfile`、`ApiError.fieldErrors?`。
- 会话存储（O13）：`memory`（token 仅存 `App` React state；不落 localStorage/sessionStorage）。
- 联调（O9）：`proxy_ready`（`vite.config.ts` `server.proxy['/api']`）且 `cors_ready`（`SecurityConfig.corsConfigurationSource` 允许 :5173，`PUT` 已在允许方法中）。
